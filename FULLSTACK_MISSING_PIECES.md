# Full Stack Implementation - Missing Pieces

This document outlines what is NOT covered in Phase 2, 3, and 4 design documents, but must be designed and implemented to complete the full stack transformation.

## 1. File Indexing & Storage Layer ❌

### Currently handled by:
```
├─ File upload (ktem/index/file/ui.py)
├─ File loading (DirectoryReader)
├─ Chunking (TokenSplitter, LLMBasedChunker)
├─ Vector Store (Chroma)
├─ Document Store (LanceDB)
└─ Embeddings (e5-small)
```

### MISSING: How does this integrate with new agents?
- Does RetrieverAgent call vector stores?
- How are chunks stored/indexed?
- Where do embeddings get generated?
- How does batch document processing work with distributed agents?
- Should indexing happen per-agent or centralized?
- How do we handle document updates/deletions in distributed system?
- Storage consistency across agent instances?

### Questions to Answer:
1. RetrieverAgent needs to query both Vector DB and potentially SQL DB via MCP
   - How does it call Kotaemo's Chroma?
   - How does it call MCP SQL tool?
   - How are results combined?

2. Document storage:
   - Single centralized Chroma/LanceDB or per-agent replica?
   - How to keep replicas in sync?
   - Caching strategy for frequently accessed documents?

3. Embedding generation:
   - Who generates embeddings during indexing?
   - Lazy vs eager embedding?
   - Caching embeddings for new uploads?

4. Batch indexing in distributed system:
   - File upload → where?
   - Trigger indexing on all agents?
   - Coordination between indexing and querying?
